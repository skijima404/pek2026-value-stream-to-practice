# 編集判断

Repositoryから見える人間とAIの協業モデルは、
学びとして非常に強く、実質的にはRepositoryそのものが本番ともいえる。

一方、今回の登壇では、
「付箋とValue Streamで地道に戦う」ことを前面に出したい。

人間とAIの協業モデルを詳しく説明すると、
それだけで別の登壇が一本成立する。
本編で大きく扱うと、
AI Slopを防ぐための価値仮説、Reasoning Chain、
Value Streamによる検証という主題が入れ替わる可能性がある。

したがって、登壇では次の役割分担にする。

- 本編の主役
  - 付箋を使ってProblemとValue Hypothesisを構築する
  - Reasoning Chainの強度を確認する
  - Value Stream上で仮説を検証する
  - 価値のあるものを選び、価値が弱いものを捨てる
- Repositoryの役割
  - この方法を登壇準備そのものへ適用した実例
  - 人間とAIの協業モデルを確認できる実行Log
  - 本編で説明しきれない学びを持ち帰るための公開資料

# 登壇での扱い

Repositoryの協業モデルは、補足として一枚で概観する。

その一枚で説明する候補:

- AIで狙うOutcomeは、生成速度だけではない
- 認知・探索の領域を広げる使い方がある
- 構造化、反証、追跡によって意思決定品質を上げる使い方がある
- このRepositoryでは、人間が意図と採用判断を持ち、
  AIが記録、構造化、反証、追跡を支援している

一枚の目的は、協業モデルを完全に理解してもらうことではない。

> Repositoryへの導線を置き、続きを見たい気持ちにさせる。

これができれば、この一枚の役割は果たしたものとする。

# 口頭での接続候補

> この話を始めると、別の登壇が一本できてしまいます。
> 今日は、AIで意思決定品質を上げる使い方もある、
> というところまでざらっとご紹介します。
> 実際の思考LogとRepositoryはそのまま公開するので、
> 興味がある方は後でご覧ください。

# Repositoryで見せたいもの

- 人間が粗い状態で考えた内容
- AIがどのように整理、解釈、追加展開したか
- 人間が何を訂正、却下、採用したか
- どの主張が未検証のまま残っているか
- 最終成果物が、どのSourceと判断から生まれたか

# この判断の成功条件

- 本編の中心が、付箋とValue Streamから逸れない
- 一枚だけでも、AI活用のOutcomeが速度以外にもあると伝わる
- Repositoryが単なる資料置き場ではなく、実践例だと伝わる
- 詳細を知りたい参加者が、登壇後にRepositoryへアクセスできる
- Repositoryを見た参加者が、本編で省略した協業モデルを追跡できる
